# AGENTS.md

Guidance for AI coding agents working in this repository. Focus: architecture and the invariants you must not break.

> The project is **experimental**. Breaking changes between commits are expected; prefer matching current code over preserving old APIs.

## What this is

**QiTech Framework** — a Rust framework for building industrial machine control software on top of **EtherCAT**, **Modbus RTU** and the **Xtrem** scale bus. A user defines a *machine* (Rust struct + YAML schema), registers it with a *Runtime*, and the Runtime runs a hard real-time-ish control loop while streaming reports to a *controller* (TUI or Hub) over a session protocol.

Hardware drivers (EtherCAT HAL, Beckhoff/WAGO modules, Modbus, Xtrem, `uom` units) live in the external crate `qitech_lib` (git dependency pinned by `rev` in the root `Cargo.toml`), not in this repo.

## Core concepts

### Machine identification
- `MachineIdentification { vendor_id: u16, machine_id: u16 }` — the machine *type*. Vendors are listed in `qitech_framework_core/vendors.toml` (codegen'd by `build.rs`; QiTech = 1).
- `MachineInstanceIdentification { machine, serial: u16 }` — a concrete machine; packs into a `u64` (`vendor<<48 | machine<<32 | serial`) and displays as `vendor:machine:serial`.

### Machine schema (YAML)
Each machine type has a schema file, found by the macros at `<crate>/<schema-dir>/<snake_case(StructName)>.yaml`. `schema-dir` defaults to `schemas` and can be overridden via `[package.metadata.qitech] schema-dir = "..."`.

```yaml
qms_version: 1.0          # schema format version
revision: 1               # revision of this machine's schema
identification: { name: laser_v1, vendor_id: 1, machine_id: 6 }
config:                   # ConfigProperty — writable by controller and machine
  diameter:
    target: !millimeter   # nested keys form the resource path "diameter.target"
state:                    # StateProperty — machine-owned, read-only externally
  in_tolerance: !boolean
measurements:             # Measurement — sampled values
  diameter_x: !?millimeter   # "?" prefix = nullable (Option<T>)
events:
  out_of_tolerance: !event
```
Tags: `!boolean`, `!integer`, `!string`, `!enum`, `!float`, or any unit/quantity from `qitech_framework_core/quantities.toml` (which also drives the `with_uom_quantities!` macro generated by `build.rs`). Parsing lives in `qitech_framework_core/src/schema/parser/` (a line pre-processor followed by serde).

### Authoring a machine
```rust
#[derive(Machine)]                      // emits MachineDescriptor { IDENTIFICATION, SCHEMA }
struct MyMachine { led: ConfigProperty<bool>, dev: Rc<RefCell<EL2004>> }

impl Machine for MyMachine {            // act(dt), subscribe(ctx), unsubscribe(ident)
    fn act(&mut self, dt: Duration) -> ActResult { Ok(()) }
}

impl MachineBuild for MyMachine {
    #[machine_build(MyMachine)]         // validates ctx.config("path") calls against the schema
    fn build(ctx: &mut BuildContext) -> BuildResult<Self> {
        let dev = ctx.find_ethercat_device::<EL2004>(1)?;   // by role
        let led = ctx.config::<bool>("led1_on")
            .on_external_changed(|m: &mut MyMachine| m.apply())
            .build()?;
        Ok(Self { led, dev })
    }
}

RuntimeConfiguration::new()
    .ethercat(EtherCATConfig::default())
    .machine::<MyMachine>();
```
- `BuildContext` builders: `config`, `state`, `measurement`, `command` (`can_execute`, `execute`), `event`; hardware lookups: `get/find_ethercat_device[_addr]`, `get_modbus_rtu_device`, `get_xtrem_device`, `get_xtrem_probe`, `get_ethercat_interface`.
- `#[machine_build]` gives a **compile error** for an unknown config path, a nullable/`Option` mismatch, or a quantity type mismatch. Enum and string configs need an explicit turbofish.
- Custom enums used as properties must `#[derive(EnumProperty)]`. Variant names are matched in snake_case.
- `ActError` has an `impact`. Only `ActErrorImpact::Irrecoverable` removes the machine from the loop (it is `swap_remove`d and `RuntimeEvent::RemovedMachine` is reported).

## Runtime architecture (`qitech_framework/src/runtime/`)

### Threading model
The Runtime is **single-threaded and synchronous** (`Rc`, `RefCell`, `Cell`, raw pointers — deliberately not `Send`). The entry points spawn it on its own `std::thread`. The controller (TUI/Hub) runs on tokio in the main thread. The EtherCAT HAL runs its own thread and exchanges process data via a triple buffer (`TripleBufConsumer`).

### Initialization (`init.rs`) — driven by the session handshake
1. `provider.provide()` → `SessionHandshake`; `begin_sync()` sends `Hello` (magic + protocol version), expects `HelloAck`.
2. For each registered machine: parse the schema, reject duplicate identifications, and `sync(schema)` → the controller sends `SchemaAck`/`SchemaReject`.
3. `begin_initialization()` → hardware bring-up, streaming `RuntimeInitEvent`s:
   EtherCAT discovery (`ethercat.rs`) → Modbus RTU devices by serial path (`modbus_rtu.rs`) → Xtrem bus (`xtrem.rs`). Discovered devices land in a `HardwareRegistry` keyed by `MachineInstanceIdentification`.
4. Build machines (`init_machines`). Each build runs inside a `PropertyRegistrar` transaction: if the build fails, the registrar's `Drop` **rolls back** allocations and descriptors.
5. Finalize EtherCAT (bring the bus to Op), then announce `MachineBuildCompleted` per machine.
6. `upgrade()` → `SessionRunning`; the transport is switched to **non-blocking**.

### The cycle (`mod.rs::tick`, default period 100 µs)
```
controller alive? → write_ecat_inputs → process_requests (≤ requests_per_cycle_max)
→ run_machines(dt) → sync_cache (config/state/measurement) → write_ecat_outputs
→ record timings → export_report_if_due (default every 1/32 s) → sleep remainder
```
Defaults live in `runtime/types.rs::Config`. Override them via `RuntimeConfiguration::{cycle_period, export_interval, requests_per_cycle_max}`.

### Resource storage (`qitech_framework/src/resource/`)
- `ResourceRegistry` holds three `PropertyRegistry`s (config, state, measurements). Each has **two `BumpAllocator`s** of equal size (4096 bytes by default): `value` (live, written by the owning machine) and `cache` (snapshot).
- `sync_cache()` memcpys value → cache once per cycle. Other machines read the **cache** through `RemoteProperty<T>`, so cross-machine reads always see a consistent end-of-cycle snapshot.
- Property handles hold `NonNull<T>` into the allocators. Pointers stay valid because allocators never grow or reallocate. If a pool fills up, it panics (`"bump allocator exhausted"`).
- `LifetimeToken`/`LifetimeTokenOwner` (a `Weak`/`Rc` pair) guard subscriptions. Accessing a `RemoteProperty` after unsubscribe **panics** by design.
- **Journals** (`journal.rs`) buffer config/state/command/event records with timestamps. They are drained into the `RuntimeReport` on export.

### Requests (`request.rs`)
`RuntimeRequestKind`: `SetConfigProperty`, `ExecuteCommand`, `SubscribeMachine`, `UnsubscribeMachine`, `WriteMachineDeviceInfo` (writes machine identity to an EtherCAT device EEPROM). Each yields a `RuntimeResponse { request_id, result }`, which is placed in the next report.

## Session protocol (`qitech_framework_core/src/session/`)

- Messages (`protocol.rs`): `RuntimeMessage { Hello, Schema, InitEvent, Finished, Report }` and `ControllerMessage { HelloAck, HelloReject, SchemaAck, SchemaReject, Request }`.
- The handshake is encoded as **typestate** on both sides (`runtime.rs`, `controller.rs`): `SessionHandshake → SessionSyncingSchemas → SessionInitializing → SessionRunning`. Add new phases as new types, not as runtime flags.
- Transports implement `RuntimeTransport` (sync, can switch to non-blocking) or `ControllerTransport` (async):
  - `mpsc(capacity)` — in-process tokio channels. Used by `run_with_tui` and `run_with_hub`.
  - `unix` — Unix domain socket with a postcard-based `Codec`.
  - `debug` — `DebugRuntimeSessionProvider`, used by `run_debug` (no real controller).
- Bump `PROTOCOL_VERSION` in `protocol.rs` when you change wire types.

### Invariants (see `docs/protocol.md`), which must hold
1. Exactly one controller session at a time.
2. Machine execution is never blocked by data delivery.
3. Reports are ordered and never intentionally dropped; missing reports are not tolerated.
4. The controller is responsible for buffering, persistence and distribution. The Runtime is not a broker.
5. Under backpressure, or if the session is lost, the Runtime **terminates** rather than buffering, dropping or reconnecting. A new session requires a full resync.

## Controllers

- **Hub** (`qitech_framework_hub`): `run(config, provider)` spawns three things into a `JoinSet`. `session_manager` runs the handshake and schema sync, forwards reports to a `broadcast` channel, and notifies `Listener`s (`on_schema_sync`, `on_init_event_received`, `on_report_received`, `on_runtime_disconnected`). `transaction_manager` assigns `request_id`s and matches responses to `oneshot` responders. Actors are user `Actor::run(ActorContext)` futures that send requests via `ctx.send_request(kind)`. Shared registries use `arc-swap` (`Swappable<T>`).
- **TUI** (`qitech_framework_tui`): `Tui::create(config).run(provider)`. It is organized as `root.rs` → `widgets/` (per-panel views) → `components/` and `controls/` (reusable UI pieces), with `session.rs` bridging the controller session.

## Build, run, test

- Toolchain: pinned in `rust-toolchain.toml` (1.90.0, edition 2024). There is also a `shell.nix`.
- `cargo build` / `cargo check --workspace` / `cargo clippy --workspace`
- `cargo test -p qitech_framework_core` (includes `tests/session_unix_tokio.rs`)
- `cargo run -p beckhoff_el2004` (package name = example dir name)
  - `.cargo/config.toml` sets `bin/run-linux` as the runner. It calls **`sudo setcap`** (`cap_net_raw`, `cap_sys_nice`, `cap_ipc_lock`, `cap_dac_override`) on the binary and `chown`s `/dev/ttyUSB*`. Expect sudo prompts, and don't run examples in unattended/CI contexts without real hardware.
- Formatting: `rustfmt.toml` uses `imports_granularity = "Item"` (one `use` per item) and `group_imports = "StdExternalCrate"`. Match this style.

## Conventions

- Section comments look like `// --- name ---`. Keep that style.
- Public authoring API is exported from `qitech_framework` (`machine::*`, `runtime::*`, crate root). Items the macros need go through `qitech_framework::__private`. Keep that path stable when you change macros.
- Anything that crosses the session must be `Serialize + Deserialize` and live in `qitech_framework_core` (`report/`, `request.rs`, `schema/`).
- The runtime hot path must not allocate unboundedly, block, or do I/O other than the non-blocking session and the EtherCAT triple buffer.
- `unsafe` is concentrated in `resource/` (bump allocator, typed pointer casts guarded by `TypeId` checks). If you change a property layout or type, preserve those `TypeId` checks.
